# Maintained ESLint qualification

Tracks [issue 30](https://github.com/patchwerks/furbomek/issues/30) and
[PR 35](https://github.com/patchwerks/furbomek/pull/35). Base:
`fb7e25e9982f53a1f12e6c63955420ac476d8294`. The implementation is qualified on
Linux Node 22.22.3 and 26.7.0 at
`1290a43d16c12afc019d7c913a6faaf57854f67e`; independent acceptance remains
required. Existing lint errors remain, so issue 30's clean-lint criterion is
**not met**. No application source, trusted worker or dispatcher changed.

## Selected graph and provenance

The manifest selects `@nuxt/eslint` 1.17.0, ESLint 10.14.0 and
`@eslint/config-inspector` 3.2.0. The [official support table](https://eslint.org/version-support/)
marks ESLint 9 EOL since 2026-08-06. The
[Nuxt module metadata](https://registry.npmjs.org/@nuxt%2feslint/1.17.0) accepts
ESLint 10 and requires inspector ^3.2.0. Inspector
[1.3.0](https://registry.npmjs.org/@eslint%2fconfig-inspector/1.3.0) accepts only
ESLint 8/9, so retaining it cannot meet the single-maintained-major goal without
an impermissible peer bypass. Its replacement
[3.2.0](https://registry.npmjs.org/@eslint%2fconfig-inspector/3.2.0) accepts ESLint
10 and passed the static-build qualification below. No override, forced peer
resolution or rule suppression was used. Metadata accessed 2026-11-01 local date.

The exact lock was generated by
[run 41242150906](https://github.com/patchwerks/furbomek/actions/runs/41242150906)
from `2c5add537e15fed3af631589de6717ca2a8f1935` and imported without editing its
bytes. SHA-256:
`5cdc4b0cf102c30d3a8693e0584802c252f75d7f5bed81d0a13340ac158e73d0`.
All 12 non-lint direct resolved versions remain unchanged. The graph contains
one ESLint 10.14.0, inspector 3.2.0 and one esbuild 0.28.2.

This is not a lint-only transitive update. There are 458 package-path version
differences: 247 removed, 133 changed and 78 added. They include Nuxt/tooling
hoisting, upgraded lint plugins, Rollup 4.66.0 to 4.67.3, ws 8.22.0 to 8.22.1
and changes in other shared transitives. The run artifacts include
`direct-versions.json` and `transitive-delta.json` for review.

## Preserved rule semantics

The generated Vue/TypeScript configuration remains authoritative. Effective
configuration review caught two compatibility gaps and the wrapper preserves
the old enforcement:

- Nuxt stopped enabling `import/no-self-import`; the existing import-x 4.17.1
  rule is explicitly restored at error severity.
- ESLint 8 defaults `no-constant-condition` to all loops, whereas ESLint 10
  defaults to `allExceptWhileTrue`. Explicit `checkLoops: 'all'` preserves
  checks on `while (true)`.

Exact published [8.57.1](https://registry.npmjs.org/eslint/-/eslint-8.57.1.tgz)
and [10.14.0](https://registry.npmjs.org/eslint/-/eslint-10.14.0.tgz) rule sources
were inspected as inert archives. Of the other 17 printed option differences,
15 expose equivalent defaults: no-cond-assign, no-empty, no-empty-pattern,
no-extra-boolean-cast, no-fallthrough, no-global-assign, no-invalid-regexp,
no-irregular-whitespace, no-misleading-character-class, no-self-assign,
no-unsafe-optional-chaining, no-useless-escape, use-isnan, prefer-const and
TypeScript no-unused-expressions. The TypeScript plugin remains 8.72.1.
The new relational-comparison flag is false, preserving prior scope; the new
reportGlobalThis flag is true, strengthening checks.

Both final jobs reported zero removed/decreased enabled baseline rule
severities. Temporary Vue and TypeScript files that self-import and contain
`while (true)` each produced exactly the expected `import/no-self-import` and
`no-constant-condition` errors, with no fatal errors, under baseline and
candidate. The fixtures were created only in network-none workers and removed
before inspector generation. They exercise the real parser/import resolution
and rule execution, not just configuration text.

## Boundary, earlier attempts and acceptance limits

The workflow is manually/issue-branch triggered advisory qualification. It uses
fixed image/action digests, an immutable baseline proxy, rootless bounded
containers, read-only sanitized source and tmpfs scratch. Tracked symlinks,
gitlinks, npm configuration and environment files are rejected before staging.
Networked workers run only script-disabled dependency provisioning; fresh
network-none workers execute all source/build/lint/inspector work. Bounded
allowlisted inert evidence is validated before export; owned resources are
removed and checked absent. No credentials, host home, Docker socket, production
network, devices, provider calls, deployment or live services are involved.

Initial incremental resolution failed in runs
[41241461518](https://github.com/patchwerks/furbomek/actions/runs/41241461518) and
[41241726222](https://github.com/patchwerks/furbomek/actions/runs/41241726222).
The separately reviewed fresh-resolution strategy temporarily pinned all
non-lint direct dependencies to accepted versions in disposable scratch, used
normal npm resolution, restored original manifest bytes and verified all those
direct versions stayed fixed. Run 41242150906 then stopped at the documented
baseline peer problem. Run 41242812117 qualified both runtimes and exposed the
two rule gaps subsequently corrected and requalified by run 41243358411.

Independent exact-head review and issue acceptance remain open. The clean-lint
criterion needs a separately scoped debt fix or an explicitly accepted change
to that criterion; this PR does not silently waive it. Reverting manifest,
lock and wrapper together restores the former toolchain, including its EOL
ESLint 8 runtime. No installed runtime or hardware was changed.
